|---|---|---|
| Model | DeepSeek-R1-Distill-Qwen-7B, RedHatAI w8a8 quantization, revision `925259de`. The November 9 gate also used RedHatAI Qwen2-7B-Instruct w8a8 | Other models, other quantizations, bf16/fp16 R1 |
| Engine | November 9: frozen v27 (`795c71736e22e2f6`). Any CPU full-suite run: the package refuses `full-suite --device cpu` (exit 2) |
| Small Qwen checks and gate (November 9 only) | 2/2 small Qwen2-7B checks on each CPU model; a 92-case Qwen2-7B gate on each GPU type | Not repeated with the package |

| Performance | November 9: one measured run per setting, rental rates observed that day, NVML GPU-board energy. | Signatures | Ed25519 records verified offline against a chosen public key; changed tokens, fingerprints, prompts, seeds, temperatures, dropped tokens, re-signed forgeries and wrong keys rejected | A signature does not show which machine ran a job or that an answer is correct |
| Platforms | Linux x86_64, NVIDIA GPUs on one cloud (RunPod), Intel and AMD x86_64 CPUs | AMD or Apple GPUs, ARM CPUs, macOS, Windows, other clouds |
| Evidence retained | See the completeness statement in the November 9 folder: per-GPU result files and the 17 signed H100 NVL records are public; the 136 answers each GPU produced (and their signed records) are not in the recovered archive | - |

## September 2026: Qwen2-7B on H100 (historical)

Scope of the historical LuxiEdge Qwen2-7B inference results in [`INFERENCE.md`](INFERENCE.md#historical-qwen2-7b-on-h100-september-2026) and [`BENCHMARKS.md`](BENCHMARKS.md). Raw files: [vLLM evidence](evidence/h100-qwen2-7b-vs-vllm-0.25.1-2026-09-25/) · [SGLang evidence](evidence/h100-qwen2-7b-vs-sglang-0.5.19-2026-09-26/) · [Drift demo evidence](evidence/h100-qwen2-7b-drift-demo-2026-09-26/).

| Topic | Tested | Not tested |
|---|---|---|
| Model | Qwen2-7B-Instruct only | Any other model or model size |
| GPU | One NVIDIA H100 SXM 80GB per run. The vLLM runs (2026-09-25/26) and the SGLang runs (2026-09-26) used two different RunPod pods | Other GPUs; multi-GPU or multi-node setups. Do not mix absolute numbers across the two pods: compare each engine only with the Luxi runs from its own pod |
| Precision | Luxi: fp16. vLLM: fp16. SGLang deterministic mode: fp16 and bf16. SGLang normal mode: fp16 | Luxi in bf16, fp8 or other quantized formats |
| Engine versions | vLLM 0.25.1. SGLang 0.5.19, the last SGLang release built for CUDA 12 (the pod driver was CUDA 12.8) | Newer SGLang releases (0.5.20 needs CUDA 13) |
| Speed and energy tests | Prompt-only: 2,048 tokens × batch 16, 8,192 × 4, 32,767 × 1, and 1,024 × 1, 16 and 64. Generation: 1,024-token prompt plus 256 greedy tokens at batch 1, 16 and 64 | Other prompt lengths and batch sizes; sampled (non-greedy) decoding; mixed-length or live request traffic |
| Run design | Engines alternated in matched blocks on the same GPU. Each block ran 3 runs of 12 seconds per test, so each engine has 6 runs per test. Per-run rows are in each evidence folder's `runs/` | — |
| Normal SGLang | Ran in a separate round right after the Luxi vs SGLang deterministic round, alternating with vLLM 0.25.1 on the same GPU | Normal SGLang was not interleaved with Luxi. Luxi vs normal SGLang compares back-to-back rounds |
| Luxi determinism | The same prompt at batch 1 and at a larger batch: 2,048 tokens at batch 1 and 16; 8,192 at 1 and 4; 32,767 at 1 and 2; five short prompts (5–16 tokens) with 64 greedy tokens at batch 1 and 16; a 1,024-token prompt with 256 greedy tokens at batch 1, 16 and 64; five more short prompts (the Hugging Face check below) at batch 1 and 16. Every case ran twice. The test prompt is row 0 of the batch; the other rows are random filler prompts of the same length. Checked: a hash of the test prompt's final logits and its full list of generated tokens. The ten cases before the Hugging Face prompts gave the same hashes in two separate processes on the two different pods | Batch sizes not listed here; mixed-length batches; staggered arrivals; other GPUs or drivers |
| SGLang determinism | Deterministic mode, fp16 and bf16: 2,048 × 16, 8,192 × 4 and 32,767 × 2 prompts, alone vs in a batch with 2 different filler sets, and run to run; a 1,024-token prompt with 256 greedy tokens alone, in batches of 16 and 64 and in a staggered batch of 16, each repeated, comparing top-5 logprobs at every step | — |
| Hugging Face check | Reference: Hugging Face transformers 5.17.0, fp16, greedy with repetition penalty 1.0. On 5 short prompts Luxi's top token and ordered top-5 tokens match, with max absolute logit difference 0.017–0.034. Greedy output on the five 64-token prompts above matches all 64 tokens on 4 of them; on the fifth it diverges at token 16, a step where Hugging Face's top two tokens are tied. On the 1,024-token prompt it matches until token 248 of 256. On the vLLM pod the 2,048, 8,192 and 32,767-token prompts also gave the same top token and ordered top-5 as Hugging Face (max difference 0.032, 0.034 and 0.055) | Longer generations; task accuracy benchmarks; other reference implementations |
| Other engines vs Hugging Face (same checks) | On the 1,024-token prompt vLLM 0.25.1 (default and batch-invariant), SGLang normal fp16 and SGLang deterministic fp16 also diverge from Hugging Face at token 248, and SGLang deterministic bf16 at token 128. On the short prompts they match all 64 tokens, except SGLang deterministic bf16 on one prompt (token 56) | — |
| SGLang code | Kernels, scheduler and model code unmodified. One line in the tokenizer manager got a missing None check so the correctness check could request top-5 logprobs; the speed runs do not request logprobs | — |
| Energy | GPU board energy from NVML's total-energy counter over each run, no idle subtraction | CPU, memory, host, cooling or wall-plug power |
| Deployment | Single-GPU benchmark harness sending fixed batches to each engine in-process (vLLM and SGLang offline engine APIs, no HTTP server) | A full serving deployment: HTTP front end, live-traffic scheduling, multi-GPU or multi-node serving |
| Re-run and lifecycle savings | — | Not measured yet (for example, avoided re-runs or re-validation because outputs stay the same) |
| Third-party validation | TestFort evaluated earlier, different builds: the Version 99 matched-prefill test (2026-07-23) and the December 2025 numerical-engine report | These results. No third party has run or checked the vLLM or SGLang comparisons or the drift demo |
| Public binaries | The version-100 `luxiedge-serve` binary in [`downloads/`](downloads/) is a historical API toy (OpenAI-shaped API, toy generate path) | It is not the benchmarked engine and not the current reasoning engine. The current public inference download is the November replay package |
| Drift demo: setup | [Drift demo](INFERENCE.md#drift-demo), 2026-09-26, one H100 SXM 80GB. Qwen2-7B-Instruct fp16, greedy, 20 fixed prompts, 256 tokens each. Each output under load was compared with the same engine's output for that prompt alone. Engines: Luxi, vLLM 0.25.1 default and batch-invariant, SGLang 0.5.19 default and deterministic | Other models, dtypes or GPUs; sampled (non-greedy) decoding; repeating the whole demo |
| Drift demo: conditions | Luxi: batch 16 and 64 with two filler sets and two row positions, 80 load conditions. vLLM and SGLang: the same, plus a mixed-length batch of 16 and two live-server runs with requests arriving at different times, 140 load conditions. For the 1,698-token prompt the "64" conditions used 32 rows for every engine (Luxi buffer limit). Luxi used a 2,048-token decode context | Luxi with live-server arrivals or mixed-length batches: the benchmarked Luxi engine has no server for requests arriving at different times and its batch API takes equal-length rows. Batch sizes other than 16, 32 and 64 |
| Drift demo: what was compared | Generated tokens, visible text and logprob hashes. Luxi: logprobs at 9 positions (0, 1, 3, 7, 15, 31, 63, 127, 255) plus a hash of the full 152,064-entry logits vector at each. vLLM and SGLang: the chosen token's logprob at every position | Luxi logprobs at the other positions |
| Drift demo: Luxi long-running process | The Luxi results (80 of 80 identical) combine p01–p19 from one long-running Luxi process with p20 from a fresh-process re-run. In that long-running process, the long prompt (p20) ran after 1,043 earlier calls: its first run alone did not match the fresh-process run, its repeat alone gave the same tokens but different logits at all 9 checkpoints, and a later call stopped with a CUDA illegal-memory-access error. A fresh-process re-run of all 6 p20 conditions was fully identical. The faulty records are in [`raw/luxi_main_process_p20_fault.jsonl`](evidence/h100-qwen2-7b-drift-demo-2026-09-26/raw/luxi_main_process_p20_fault.jsonl) | The cause of the fault is open and under investigation. Consistency of a long-running Luxi process is not established |
| Drift over time | — | The same engine re-run across days, driver updates or engine updates |
