# What was and wasn't tested

Scope of the LuxiEdge Qwen2-7B inference results in [`INFERENCE.md`](INFERENCE.md) and [`BENCHMARKS.md`](BENCHMARKS.md). Raw files: [vLLM evidence](evidence/h100-qwen2-7b-vs-vllm-0.25.1-2026-09-25/) · [SGLang evidence](evidence/h100-qwen2-7b-vs-sglang-0.5.19-2026-09-26/).

| Topic | Tested | Not tested |
|---|---|---|
| Model | Qwen2-7B-Instruct only | Any other model or model size |
| GPU | One NVIDIA H100 SXM 80GB per run. The vLLM runs (2026-09-25/26) and the SGLang runs (2026-09-26) used two different RunPod pods | Other GPUs; multi-GPU or multi-node setups. Do not mix absolute numbers across the two pods: compare each engine only with the Luxi runs from its own pod |
| Precision | Luxi: fp16. vLLM: fp16. SGLang deterministic mode: fp16 and bf16. SGLang normal mode: fp16 | Luxi in bf16, fp8 or other quantized formats |
| Engine versions | vLLM 0.25.1. SGLang 0.5.19, the last SGLang release built for CUDA 12 (the pod driver was CUDA 12.8) | Newer SGLang releases (0.5.20 needs CUDA 13) |
| Speed and energy tests | Prompt-only: 2,048 tokens × batch 16, 8,192 × 4, 32,767 × 1, and 1,024 × 1, 16 and 64. Generation: 1,024-token prompt plus 256 greedy tokens at batch 1, 16 and 64 | Other prompt lengths and batch sizes; sampled (non-greedy) decoding; mixed-length or live request traffic |
| Run design | Engines alternated in matched blocks on the same GPU. Each block ran 3 runs of 12 seconds per test, so each engine has 6 runs per test. Per-run rows are in each evidence folder's `runs/` | — |
| Normal SGLang | Ran in a separate round right after the Luxi vs SGLang deterministic round, alternating with vLLM 0.25.1 on the same GPU | Normal SGLang was not interleaved with Luxi. Luxi vs normal SGLang compares back-to-back rounds |
| Luxi determinism | The same prompt at batch 1 and at a larger batch: 2,048 tokens at batch 1 and 16; 8,192 at 1 and 4; 32,767 at 1 and 2; five short prompts (5–16 tokens) with 64 greedy tokens at batch 1 and 16; a 1,024-token prompt with 256 greedy tokens at batch 1, 16 and 64; five more short prompts (the Hugging Face check below) at batch 1 and 16. Every case ran twice. The test prompt is row 0 of the batch; the other rows are random filler prompts of the same length. Checked: a hash of the test prompt's final logits and its full list of generated tokens. The ten cases before the Hugging Face prompts gave the same hashes in two separate processes on the two different pods | Batch sizes not listed here; mixed-length batches; staggered arrivals; other GPUs or drivers |
| SGLang determinism | Deterministic mode, fp16 and bf16: 2,048 × 16, 8,192 × 4 and 32,767 × 2 prompts, alone vs in a batch with 2 different filler sets, and run to run; a 1,024-token prompt with 256 greedy tokens alone, in batches of 16 and 64 and in a staggered batch of 16, each repeated, comparing top-5 logprobs at every step | — |
| Hugging Face check | Reference: Hugging Face transformers 5.17.0, fp16, greedy with repetition penalty 1.0. On 5 short prompts Luxi's top token and ordered top-5 tokens match, with max absolute logit difference 0.017–0.034. Greedy output on the five 64-token prompts above matches all 64 tokens on 4 of them; on the fifth it diverges at token 16, a step where Hugging Face's top two tokens are tied. On the 1,024-token prompt it matches until token 248 of 256. On the vLLM pod the 2,048, 8,192 and 32,767-token prompts also gave the same top token and ordered top-5 as Hugging Face (max difference 0.032, 0.034 and 0.055) | Longer generations; task accuracy benchmarks; other reference implementations |
| Other engines vs Hugging Face (same checks) | On the 1,024-token prompt vLLM 0.25.1 (default and batch-invariant), SGLang normal fp16 and SGLang deterministic fp16 also diverge from Hugging Face at token 248, and SGLang deterministic bf16 at token 128. On the short prompts they match all 64 tokens, except SGLang deterministic bf16 on one prompt (token 56) | — |
| SGLang code | Kernels, scheduler and model code unmodified. One line in the tokenizer manager got a missing None check so the correctness check could request top-5 logprobs; the speed runs do not request logprobs | — |
| Energy | GPU board energy from NVML's total-energy counter over each run, no idle subtraction | CPU, memory, host, cooling or wall-plug power |
| Deployment | Single-GPU benchmark harness sending fixed batches to each engine in-process (vLLM and SGLang offline engine APIs, no HTTP server) | A full serving deployment: HTTP front end, live-traffic scheduling, multi-GPU or multi-node serving |
| Re-run and lifecycle savings | — | Not measured yet (for example, avoided re-runs or re-validation because outputs stay the same) |
| Third-party validation | TestFort evaluated earlier, different builds: the Version 99 matched-prefill test (2026-07-23) and the December 2025 numerical-engine report | These results. No third party has run or checked the vLLM or SGLang comparisons |
| Public binaries | The version-100 serve binary in [`downloads/`](downloads/) is a demo server (OpenAI-shaped API, toy generate path) | It is not the benchmarked engine, which is private |
| Drift over time | — | Not part of these results. See [Drift demo](INFERENCE.md#drift-demo) |
